# 事実訂正メモリ（hallucination-memory）

エージェントが **事実そのものを間違えた（ハルシネーションした）** とき、訂正された正しい事実を恒久メモリに残し、**毎セッション読み込んで二度と同じ誤りを犯さない** ようにする。NousResearch/hermes-agent の「閉じた学習ループ（誤りからの記憶）」の発想を、belta の決定的フック＋メモリ層として移植したもの。

- 保存先: `~/.belta/memory/MEMORY.md`（索引・運営モードで毎回読込）＋ `~/.belta/memory/<slug>.md`（個別の事実、必要時に読込）。
- 起動の土台（決定的）: `hooks/repeat-detect.js`（同一セッション内で訂正 2 回）＋ `hooks/session-start.js`（別々のセッションで同じ訂正 2 回）が `looksLikeCorrection`（`hooks/repeat-util.js`）で訂正を検知し、記録を促すコンテキストを注入する。
- 最終判断（本当にハルシネーションか・同じ誤りの再発か）は LLM（このスキル）が確定する。

> **rule-learning との住み分け（重要）**: rule-learning は **明示ルール／振る舞いの訂正**（「箇条書きで」「次回からは敬語で」＝*どう振る舞うか*）。hallucination-memory は **事実の訂正**（「その API は存在しない」「デプロイ先は A でなく B」＝*何が正しいか*）。利用者の好み・口調・書式の指摘は **rule-learning** へ回し、事実そのものの誤りだけをここで記憶する。

## いつ使うか（トリガ）

- フックが「事実訂正メモリ検知（ハルシネーション再発の可能性）」コンテキストを注入したとき。
- 利用者が事実を訂正したとき（「それは違う」「そんなファイルはない」「事実と違う」「存在しない」「正しくは〜」「ハルシネーションだ」「captionではなく caption です」等）で、**同じ誤りが 2 回以上** のとき。
- 「これを覚えておいて」「二度と間違えないで」と事実について明示的に言われたとき（この場合は 1 回でも記録してよい）。

## ワークフロー

### Step 0: 本当にハルシネーションの再発か確認

記録は恒久的で毎セッション読み込まれるため、**事実の誤りに限る**。次を確認する：

1. **事実の誤りか** — 振る舞い・好み・書式の話なら rule-learning へ回す。曖昧なら利用者に「これは事実の訂正ですか、それとも進め方の好みですか」と確認する。
2. **再発か（2 回以上）** — `~/.belta/memory/MEMORY.md` と直前の会話を確認し、あなたが同じ事実を 2 回以上間違えたかを判断する。1 回限りの言い間違い・利用者自身のミスの訂正は記録しない（明示依頼があれば 1 回でも可）。
3. **正しい事実が確定しているか** — 利用者が示した「正しい事実」が明確か。曖昧なら確認してから記録する（誤った事実を記憶すると逆効果）。

### Step 1: 記録を提案

`AskUserQuestion`（記録する / 今回は不要、＋自由記述）で確認する：

> 「『○○』について同じ誤りを繰り返してしまいました。正しくは『△△』ですね。二度と間違えないよう記憶しておきますか？」

### Step 2-a: 承認 → memory に記録

1. [references/memory-template.md](references/memory-template.md) の雛形に従い、`~/.belta/memory/<slug>.md` を **Write ツールで生成** する。
   - `slug` は kebab-case（例: `deploy-target-host`, `api-no-such-endpoint`）。
   - 本文に **「誤った主張（wrong）」「正しい事実（correct）」** を必ず並記する（何を二度と言ってはいけないかが一目で分かるように）。
   - `sources`（検知元の `notes/YYYY-MM-DD.md` やセッション）、`occurrences`（観測回数）を記録する。
2. 索引 `~/.belta/memory/MEMORY.md` に **1 行追記** する（無ければ初期化、後述）。MEMORY.md は運営モードで毎回読み込まれる。
3. 「記録しました。今後『○○』は『△△』として扱い、二度と同じ誤りはしません」と返す。

> 短く 1 文で収まる事実なら、個別ファイルを作らず MEMORY.md に直接 1 行で残してよい（軽量運用）。詳細な背景・出典が必要なものだけ `<slug>.md` を作る。

### Step 2-b: 拒否 → 記録しない

`MEMORY.md` 末尾の管理コメントに `rejected` を控える（任意）。**同じ事実の記録を 3 回連続で却下されたら 14 営業日の冷却**（提案停止）に入る（しつこく聞かない。他の提案系スキルと統一）。

## 運営モードでの利用（再発防止の要）

このメモリが効くのは **毎セッション読み込まれて、応答前に参照される** から。運営モード起動時、`profile.md` / `RULES.md` / `AGENTS.md` / `user-model.md` と並べて `~/.belta/memory/MEMORY.md` を Read し、文脈に載せる。

- 事実に関わる応答をする前に、MEMORY.md に該当する「誤った主張」が無いか確認する。あれば、その「正しい事実」に従い、**誤った主張を二度と述べない**。
- 個別の背景が要るときだけ `<slug>.md` を Read する。

## MEMORY.md の管理（常に LLM 文脈に読込）

`~/.belta/memory/MEMORY.md` は起動時に毎回 Read される索引。誤り→正しい事実を 1 行で追跡する。

### 初期化（無ければ作成）

```markdown
# MEMORY — 事実訂正メモリ（ハルシネーション再発防止）

このファイルは hallucination-memory が記録・追記する。運営モードで毎回読み込まれる。
各行は「過去に間違えた事実」と「正しい事実」。応答前に必ず照合し、誤った主張を二度と述べないこと。

<!-- 形式: - <topic>: ❌<誤った主張> → ✅<正しい事実> [src:YYYY-MM-DD / occ:n / recorded:YYYY-MM-DD]（詳細は <slug>.md） -->
```

### 追記 1 行の形式

```
- デプロイ先ホスト: ❌ deploy は staging-a に出す → ✅ 本番デプロイ先は prod-b（staging-a は検証専用） [src:2026-06-04 / occ:2 / recorded:2026-06-04]
```

- 上限の目安 200 行。超えそうなら古い・重複を統廃合する（RULES.md と同様）。

## セキュリティ・運用上の注意

- 記録するのは **検証済みの事実** のみ。利用者が確信を持って訂正した事実だけを残す（不確かな推測を記憶しない）。
- **PII・機密値そのもの**（パスワード・カード番号・マイナンバー等）は memory に書かない。「正しい事実」を抽象化して残す（例: 値そのものでなく「○○の値は△△の場所にある」）。PII 検知フック（`hooks/pre-tool-use.js`）は外部送信時の防御で、memory はローカル保存だが、念のため最小限に留める。
- `~/.belta/memory/` はホーム側・`.gitignore` 対象でリポジトリには出ない。パスはホームディレクトリ環境変数（POSIX: `$HOME` / Windows: `%USERPROFILE%`）から解決し、Write ツールで書く（`mkdir`/`touch` を必須経路に置かない）。
- このスキルはルール生成・subagent 生成・自動化はしない（それぞれ rule-learning / agent-learning / skill-* の領分）。残すのは「事実の記憶」だけ。
