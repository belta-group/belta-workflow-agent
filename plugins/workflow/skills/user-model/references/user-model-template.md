# user-model.md 雛形

`user-model` スキルが `~/.belta/user-model.md` を生成・更新するときの構成テンプレート。
観察ベースの暗黙傾向を人間可読でまとめる。**指示ではなく傾向** であることを明示する。

---

## frontmatter

```yaml
---
owner_email: <profile.md と同じ。突合用>
updated_at: <YYYY-MM-DD>   # 最終更新日
source_window_days: <走査した日数>
---
```

## 本文構成

```markdown
# ユーザーモデル（観察ベースの暗黙傾向）

> これは利用者が明示していないが notes から読み取れる「傾向」のメモ。指示ではない。
> 明示指示（profile.md / rules/）が常に優先する。確信度と出典付きで残す。

## 常用ツール
- <Notion / Slack / GitHub / Google Drive のどれをよく使うか> 〔確信度: 高/中/低・出典: YYYY-MM-DD, YYYY-MM-DD・更新: YYYY-MM-DD〕

## 繰り返す業務
- <頻出テーマ（意図でまとめる）> 〔確信度: …・出典: …〕

## 段取りの好み
- <進め方の傾向（例: 送る前に必ず確認したい / 箇条書きで欲しい）> 〔確信度: …・出典: …〕

## 言い回し・口ぐせ
- <依頼表現の癖（あれば）> 〔確信度: …・出典: …〕

## 作業の時間帯
- <朝に多い / 夕方に多い 等（弱い手がかり。確信度は低めに）> 〔確信度: 低・出典: …〕

## 候補（未確定）
<!-- 確信度「低」の観察はここに置き、本編に混ぜない。回数が増えたら本編へ昇格 -->
- <観察したが確信が持てない傾向> 〔出現: n 回・出典: …〕

## 変更履歴
<!-- 傾向が変わったら古い記述を消さずここに残す（履歴性） -->
- YYYY-MM-DD: <何がどう変わったか（前は X、最近は Y）>
```

## 更新ルール

- 既存ファイルを Read → 項目ごとに **統合**（同じ観点は上書きでなく確信度・出典・更新日を更新）。
- 確信度の目安: 1〜2 回の出現は「候補（未確定）」、3 回以上を本編の「傾向」とする。
- 矛盾する観察が出たら古い記述を消さず「## 変更履歴」に残す。
- **profile.md は触らない**（氏名・部署・機密度はオンボーディング正本）。
- PII（個人特定情報）は書かない。傾向の抽象度に留める。
- パスはホームディレクトリ環境変数（POSIX: `$HOME` / Windows: `%USERPROFILE%`）から解決し、Write ツールで書く（`mkdir`/`touch` を必須経路に置かない）。
