# モデルティア定義（SSOT — モデル名を書く唯一の場所）

作業の種類に応じて使うモデルを切り替えるための単一の権威ソース。

> **原則**: ルール・スキル・コマンド・ドキュメントには **ティア名**（`apex` / `senior` / `mid` / `light` / `frontier`）で書き、**バージョン付きのモデル名は §2 の表にだけ書く**。モデルが世代交代したら §2 を書き換えるだけで全参照が新モデルへ切り替わる。名前を直書きすると世代交代のたびに全ファイルが陳腐化する。

---

## 1. 設計原則

1. **役割はティア名で書く** — 「Opus 5 でレビューする」ではなく「senior 以上でレビューする」と書く。
2. **モデル名を書いてよいのは §2 の表だけ**。
3. **エイリアスで指定する**（`opus` / `sonnet` / `haiku` / `fable`）。バージョン付き ID（`claude-opus-5` 等）の直書きは、同系列の世代交代に追従しないので**禁止**。
4. **賢さはケチらず、無駄遣いもしない** — 上位ティアは「短いが効く」工程（設計・判断・最終チェック・レビュー検証）に集中投下し、トークンを大量消費する工程（長文生成・一括処理・定型変換）は下位ティアか決定的スクリプトへ回す。
5. **ターン途中で自分の実行モデルは変えられない**。上位/下位の推論が必要なら「メインを切り替える」のではなく「そのティアのサブエージェントを spawn する」。

## 2. ティア → 現行モデル対応表

| ティア | 役割 | 現行モデル | 指定エイリアス | effort 目安 |
| --- | --- | --- | --- | --- |
| **apex** | 設計・最終判断・クリエイティブ最終チェック | Opus 5 | `opus` | `xhigh` 〜 `max` |
| **senior** | 複雑実装・**レビュー / 検証 / 正確性の判定** | Opus 5 | `opus` | `high` |
| **mid** | 標準実装・本文生成・通常のオーケストレーション | Sonnet 5 | `sonnet` | `medium`（省略可） |
| **light** | 整形・収集・機械作業・高頻度ワーカー | Haiku 4.5 | `haiku` | `low` |
| **frontier**（例外枠・**要事前承認**） | apex で頭打ちが実証されたときだけ | Fable 5 | `fable` | — |

- **apex と senior は同一モデル。差は effort で出す**。したがって「apex は高いから senior に落とす」というコスト判断は成立しない。落とすなら mid まで落とす。
- **frontier は単価が apex の 2 倍**。既定では使わない。使うのは apex で走らせて品質不足を確認したときだけで、投入前に費用見込みを 1 行で報告する。反復ループ・長文生成・一括処理・デバッグループには投入しない。
- **frontier は仕組みでも止めている**: `.claude/settings.json` の `ask` に `Agent(model:fable)` があるため、frontier でサブエージェントを起動しようとすると必ず確認ダイアログが出る（＝事前承認が機械的に要求される）。
- light の代替として、**固定ロジックは決定的スクリプト**（`scripts/*.js`）に落とす。トークン消費ゼロで再現性も上がる。このプラグインの `notes-scan.js` / `goal-scan.js` / `token-dashboard.js` / `skill-audit.js` はすべてこの発想。

## 3. ロール → ティア対応

| 作業 | ティア | 例 |
| --- | --- | --- |
| 要件設計・アーキテクチャ設計・経営判断の支援 | **apex** | 大型施策の設計、重要成果物の最終レビュー判定 |
| クリエイティブ・成果物の最終品質チェック | **apex** | 校閲、社外提出物の最終確認 |
| **レビュー・検証・正確性が求められる判定** | **senior 以上** | コードレビュー、構成案・文書の内容チェック、事実確認、セキュリティレビュー |
| 複雑な実装・重要文書の本文生成 | **senior** | 難所のコーディング、複雑デバッグ |
| 標準実装・通常の文章生成・分岐 | **mid** | 通常のコード実装、Notion ページ作成、Slack 下書き |
| 整形・データ収集・機械的作業 | **light** | データ整形、一括変換、定型集計（スクリプトで済むならスクリプト） |

### 🔴 レビュー・検証は mid 単体で完結させない

「合っているか / 妥当か」を**判定する**作業は、正確性の要求が高い。メインセッションだけで結論を出さず、**senior 以上のサブエージェントを spawn して判定させる**。メインの役割は情報収集・下ごしらえ・結果の取りまとめまで。

対象は「成果物・文書・構成案・コードの内容が正しいか/妥当かを判定する」作業全般。専用のレビューエージェントがあればそれを senior 以上で起動し、無いアドホックな確認依頼（例: 資料の構成チェック、外部資料のファクトチェック）でも同じ扱いにする。クリエイティブの**最終**チェックは apex。

## 4. メインセッションの扱い

- **専用フォルダの既定モデルは apex（`opus`）**。`.claude/settings.json` の `"model": "opus"` を `apply-governance.js` が専用フォルダの `settings.local.json` に配送する。既定であって強制ではないので、セッション内で `/model` で変えられる。

> 参考: 原典のティア設計では「メイン既定は mid、apex は spawn で使う」としていた。このプラグインでは**利用者判断で既定を apex に上げている**（判断の質を優先）。その代わり、次の規律を守ってコストを抑える。

- **メインが apex のときの規律**:
  1. トークンを大量消費する機械作業（一括処理・大量の定型生成・長文整形）は **light / mid のサブエージェントへ委譲**する。
  2. 単発の小さな読み書き（メモ 1 行追記・ファイル 1 つ生成）はメインで実行してよい（委譲の固定費のほうが高い）。
  3. 判断基準は「**委譲で節約できるトークン > 委譲の固定費**」。
- 消費が気になったら `/usage`（`token-usage` スキル）でモデル別内訳を確認する。Opus 比率が高いまま総量が伸びているなら、上の規律 1 が効いていないサイン。

### 例外: バージョン付き ID を書いてよい唯一の場所

**permissions の入力パラメータ照合ルール**だけは例外。`Agent(model:...)` は Claude が送るリテラル値と比較され、エイリアスと正式 ID は別物として扱われる（`Agent(model:opus)` は `opus` にマッチするが完全な ID にはマッチしない）。したがって frontier を確実に捕まえるには**両方の綴りを書く**必要がある。

```json
"ask": ["Agent(model:fable)", "Agent(model:claude-fable-5)"]
```

これは「モデルを選ぶ」記述ではなく「その綴りで来た呼び出しを捕まえる」記述なので、原則 3 の対象外。モデルが交代したら **§2 の表と一緒にこの 2 行も更新する**（照合なので新旧を残しておいても害はない）。

## 5. モデル交代時の更新手順

1. §2 の表を新モデルへ書き換える（この 1 箇所が正）。
2. 系列そのものが交代した場合のみ、下の反映先の `model:` を新エイリアスへ同期する（同系列内の世代交代はエイリアスが自動追従するので作業不要）。
3. バージョン直書きの再混入を検査する（コメント行以外のヒットが 0 であること）:

   ```
   node -e "const{execSync}=require('child_process');console.log(execSync('grep -rn \"claude-opus-\\|claude-sonnet-\\|claude-haiku-\\|claude-fable-\" plugins/ || true').toString())"
   ```

## 6. 反映先（このファイルを参照するもの）

- `.claude/settings.json` の `"model"`（メイン既定 ＝ apex のエイリアス）と `ask` の `Agent(model:fable)`（frontier の事前承認）
- `commands/workflow-setup.md` frontmatter `model: sonnet`（mid — 定型のオンボーディング処理）
- `commands/usage.md` frontmatter `model: haiku`（light — 決定的スクリプト実行＋要約）
- `skills/agent-learning/references/agent-template.md`（生成 subagent の `model:` 指針）
- `skills/workflow/SKILL.md`（レビュー・検証を senior 以上へ spawn する誘導）
