# スキル信頼ソース allowlist（skill-suggestion 用）

`skill-suggestion` が **自動インストールを提案してよい** 提供元（marketplace / source）の許可リスト。ここに無いソースのスキルは **提案のみ**に留め、自動インストールしない。

## 自動インストール可（allowlist）

| 提供元 | 識別子 | 根拠 |
| --- | --- | --- |
| **社内 marketplace** | `belta-group/*` | 社内で審査・配布する自組織のスキル。最優先で信頼する。 |
| **Anthropic 公式** | Anthropic 公式 marketplace / 公式 document・example スキル群 | 提供元が明確で、Claude Code 同梱・公式配布のもの。 |

- 上記いずれかに該当し、かつ **提供元と要求権限が提示できる** 候補のみ、Step 4 の自動インストール提案に進む。
- 判断に迷う（提供元が曖昧・要求権限が過大）場合は allowlist 外として扱う。

## 自動インストール不可（提案のみ）

- 第三者・個人作成の未審査スキル
- 提供元が特定できない、または要求権限が用途に対して過大なもの
- marketplace 識別子が `belta-group/*` でも Anthropic 公式でもないもの

これらは「こういうスキルが世の中にあります」という **情報提供と手動導入の案内** までとし、`/plugin install` を自動実行しない。導入する場合は利用者自身の判断で行ってもらう。

### 非公式スキル導入前の目視確認チェックリスト

allowlist 外（`source: third-party:*` ＝ `auto_installable:false`）を利用者が手動導入する判断材料。**取り消しにくい操作の一歩手前の安全ゲート**であり、迷ったら入れない。エージェントはこのチェックを案内し、未確認の項目が残るなら導入を見送るよう促す：

- [ ] **提供元が特定できるか** — owner / repo と配布元 URL が実在し、メンテされているか（リネーム・廃止に注意）。
- [ ] **要求権限が過大でないか** — `required_permissions` が用途に対して妥当か。広域 Write・外部ネットワーク送信（`curl`/`fetch` の POST 先）が用途と釣り合わないものは見送る。
- [ ] **SKILL.md・スクリプトを目視したか** — `rm -rf` / `sudo` / `git push` / `reset --hard` 等の破壊操作、認証情報・環境変数の外部送信、base64 等の難読化実行が無いか。
- [ ] **同等機能が allowlist 内に無いか** — `belta-group/*` / Anthropic 公式（＝自動導入可）で代替できないか `catalog-scan.js` で再確認する。あるならそちらを優先。
- [ ] **PII 検知フックは最後の砦** — `hooks/pre-tool-use.js` は導入後の新規スキル経由の書き込みにも効くが、それは**未審査スキルを入れてよい理由にはしない**（多層防御の最終段であって入口の審査を省く根拠ではない）。

## 既定の推奨スキル（手元に無ければ優先提案）

利用者の非効率作業に対して、まず検討する Anthropic 公式系スキル。多くは Claude Code に同梱・利用可能なため、**Step 1（既存スキルとの重複チェック）で「もう使える」と分かることが多い**。その場合は導入提案ではなく利用案内に切り替える。

| 作業 | 推奨スキル | 備考 |
| --- | --- | --- |
| PDF の抽出・結合・分割・OCR | `pdf` | 表・テキスト抽出、フォーム処理 |
| スプレッドシート集計・整形 | `xlsx` | xlsx / csv / tsv、数式・整形 |
| スライド作成・読み取り | `pptx` | デッキ生成・抽出 |
| Word 文書作成・編集 | `docx` | 体裁付き文書、差し込み |
| 新スキルを自作したい | `skill-creator` | スキルの新規作成・改善 |
| 何ができるか探したい | `find-skills` | インストール可能スキルの探索 |

> これらの正確な利用可否・名称はセッションの利用可能スキル一覧で確認する。同梱済みのものを「インストールが必要」と誤案内しないこと（Step 1 を必ず通す）。

## 提案時に必ず提示する情報

自動インストールを提案する前に、以下を利用者に示す（[SKILL.md](../SKILL.md) Step 4）：

- **提供元（source）**: `belta-group/*` か Anthropic 公式か。
- **要求権限（permissions）**: そのスキルが必要とするツール・外部送信の範囲。
- **用途（why）**: 利用者のどの非効率作業を、どう効率化するか。

PII 検知フック（`hooks/pre-tool-use.js`）はインストール後の新規スキル経由の書き込みにも適用されるが、それは最後の砦であって、**未審査スキルを入れてよい理由にはしない**（[security-policies.md](../../workflow/references/security-policies.md)）。
