# レポートのテンプレと「アドバイス根拠ヒューリスティクス」

`report` スキルが 4 セクション（やったこと／成長／次アクション／学ぶとよいこと）を組むときの参照知識。**すべて観察データ起点**で、根拠の無い助言（ハルシネーション）を避けるためのもの。

## 共通方針

- 結論先出し・日常語。1 セクション 1 メッセージ。
- 数値は `avatar-stats.js`、活動は `notes-scan.js` の出力だけを根拠にする。前回レポートがあれば**増分**で語る。
- 推測には「かもしれません」を付ける。事実と推測を混ぜない。
- 各セクションは短く（日報は特に簡潔）。読み手の時間を尊重する。

## 期間別の見出し構成

### デイリー（`--days 1`・簡潔）

```
# 📅 デイリーレポート（YYYY-MM-DD）

**今日のひとこと**：（1 文）

## やったこと
- （主な依頼 2〜3 点）

## 成長した点
- （今日の稼働・XP増・新バッジがあれば。無ければ「継続◯日」など事実のみ）

## 次のアクション
- （今日のやりかけ・todos/inbox の未処理から 1〜3 点）

## 学ぶとよいこと（任意・1点まで）
- （観察根拠つきで 1 つだけ。無理なら省略）
```

### ウィークリー（`--days 7`・物語）

```
# 📆 ウィークリーレポート（YYYY-MM-DD まで）

**結論**：この1週間は主に◯◯と△△をしていました。（1〜2 文）

## やったこと（繰り返したテーマ）
- （top_requests 頻度順に 3〜5 点）

## 成長した点
- （Lv/XP の伸び・新バッジ・連続稼働・ルール/エージェント/スキル増。前週比があれば増分）

## 次のアクション
- （反復依頼で未自動化のもの・抜け漏れ・未処理から 2〜4 点）

## 学ぶとよいこと
- （根拠つきの学習提案 1〜3 点）

## 次に狙える称号（任意）
- （locked バッジのうち達成が近いもの 1〜2 個と、その達成条件）
```

### マンスリー（`--days 30`・総括）

```
# 🗓️ マンスリーレポート（YYYY-MM 総括）

**結論**：今月は◯◯が伸び、△△が定着してきました。（2〜3 文）

> 注：詳細な依頼履歴は保持期間の都合で直近約14日分に基づきます。月全体の傾向は成長指標と過去レポートから補っています。

## 成長の大きな流れ
- （avatar-stats 累計：Lv・連続稼働最長・累計セッション/稼働日・ルール/エージェント/スキルの総数）

## やったこと（直近で残っている記録から）
- （残存 notes と過去レポートから主テーマ 3〜5 点）

## 今月の到達点・新しい称号
- （今月 earned に加わったバッジ。前月レポートがあれば増分）

## 来月のアクション
- （継続課題・未自動化の反復・狙う習慣を 3〜5 点）

## 学ぶとよいこと（来月のテーマ）
- （根拠つきの学習テーマ 2〜3 点）
```

## ③「次のアクション」を導く根拠ヒューリスティクス

観察 → 提案の対応づけ。該当するものだけ採用する。

| 観察（データ） | 提案する次アクション |
| --- | --- |
| `top_requests` に同じ意図の依頼が 3 回以上、かつ `raw.agents`/`skills_authored` に対応物が無い | その作業の **自動化**（rule-learning / agent-learning / skill-authoring）を検討 |
| `todos/`・`inbox/` に未処理が残っている | 未処理の棚卸し・期限の確認 |
| `sessions` にやりかけ（着手したが続きが無い）テーマ | その続きを今週/今月の TODO に |
| `usage.agent_usage` で特定エージェントに極端に偏り | 偏りの確認（他領域の取りこぼしが無いか） |
| `raw.corrections` が増えている | 訂正が出た領域の前提確認・メモ化（hallucination-memory） |

## ④「学ぶとよいこと」を導く根拠ヒューリスティクス

| 観察（データ） | 学習提案（根拠を必ず添える） |
| --- | --- |
| `usage.top_skills`/`tools` が 1 ツールに偏り、他がほぼ未使用 | 使えていないツール（Notion/Slack/GitHub/Drive）の基本を学ぶと幅が出る |
| `raw.tools` は広いが `raw.agents.adopted`/`skills_authored` が 0 | 反復作業の **自動化のやり方**（専用エージェント・スキル）を学ぶ |
| `raw.rules.by_type["mistake-fix"]` や `corrections` が多い | 繰り返し間違えている領域の基礎知識を補強 |
| `streak` が短い・`active_days` が飛び飛び | 習慣化の工夫（定期ジョブ `/workflow-schedule` の活用など） |
| `badges.locked` に手が届きそうなものがある | その達成条件が示す行動を学習目標に（例：4ツール活用→未使用ツール入門） |
| `usage.top_requests` に専門領域（例：薬機・法務・データ集計）が頻出 | その専門領域の深掘り学習が投資効果大 |

> どの提案も「なぜそう言えるか（どの数値・パターンから）」を 1 句添える。データが無い項目は提案しない（無理に埋めない）。

## やってはいけないこと

- データに無いことを「やった」「成長した」と書く（創作）。
- 投資・財務・医療など、業務スキル外の専門助言に踏み込む。
- 個人情報（PII）や機密内容をレポート本文に転記する（傾向の抽象度に留める）。
- 生のファイルパスを会話に貼る（保存先は Markdown リンクで案内）。
