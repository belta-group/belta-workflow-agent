# トラブルシューティング / FAQ

困ったときの確認事項をまとめています。アプリ連携（OAuth 接続）まわりは **[4 ツール OAuth 接続](/guide/oauth-setup#うまくいかないときは)** も参照してください。

## セットアップ

### 初回セットアップが始まりません

**「セットアップして」と話しかけるか、`/workflow-setup` を実行してください。** これで始まります。

```
/workflow-setup
```

セットアップは、画面に案内が自動で“表示”されるわけではありません。プラグインを入れただけ・待つだけでは始まらないので、上のように自分から始めてください。プラグインを入れたその会話で始まらないときは、Claude Code を開き直し、**新しい会話**で実行すると確実です。

### もう一度セットアップをやり直したい

`/workflow-setup` と打って「最初からやり直したい」と伝えてください。

一度セットアップが終わると、`~/.belta/.onboarded`（POSIX: `$HOME`、Windows: `%USERPROFILE%` の下にあるファイル）が「もう済んだ」という目印になり、自動の案内は出なくなります。手動で呼び出せば、もう一度やり直せます。

### セットアップの途中で別の用件を頼みたい

そのまま別の用件を頼んで大丈夫です。中断しても問題ありません。

セットアップが最後まで終わるまでは、`/workflow-setup` でいつでも続きから再開できます（次に Claude Code を開いたとき、アシスタントの方から促すこともあります）。やり残しは自動で拾い直されるので、好きなタイミングで再開できます。

### 秘書はどこで使うのですか（`~/my-agent` フォルダ）

**あなた専用の執務室（`~/my-agent` フォルダ）の中だけで使います。** 初回セットアップが自動でこのフォルダを用意し、その中でだけ秘書を有効にします（同名フォルダが既にあれば `my-agent-2` のような別名になります）。次回からは、この `~/my-agent` フォルダを Claude Code で開いて話しかけてください（POSIX: `$HOME/my-agent` / Windows: `%USERPROFILE%\my-agent`）。執務室に限定するのは、関係ない作業中に秘書が顔を出さないようにするためです。

### ほかのフォルダでも秘書が反応してしまいます

インストール時に「すべての場所（User スコープ）」で入れてしまった可能性があります。本来は「このフォルダだけ（Local）」で使う設計です。

`/workflow-setup` を実行すると、専用の執務室（`~/my-agent`）だけで有効になるよう付け替えられます。グローバル（すべての場所）の有効化を解除したい場合は、`/plugin` のメニュー、または `~/.claude/settings.json` の `enabledPlugins` からこのプラグインのエントリを外してください（セットアップが自動でこの設定を書き換えることはありません）。なお、グローバルで有効になっている間は、新しい会話の冒頭で「ローカル限定運用を推奨します」と知らせます。

## OAuth 接続

### `/mcp` にツールが出てこない

まず claude.ai の接続設定（Connectors）で、使いたいサービスが「接続済み」になっているか確認してください。これが一番多い原因です。

それでも出ないときは、上から順に試してください。

1. claude.ai を開き、Settings → Connectors で対象サービスが「接続済み」か確認する。
2. Claude Code を一度終了して開き直す（設定の読み直し）。
3. 自分のプランが **Max / Team / Enterprise** か確認する（アプリ連携機能（MCP）を使える条件です）。

### `gh auth status` が `Logged in` になりません

GitHub への接続をいったん切ってから、つなぎ直してください。

GitHub 用の小さな道具（gh）で、次の順に打ちます。

1. `gh auth logout`（今の接続を切る）
2. `gh auth login --web`（つなぎ直す）

ブラウザが自動で開かないときは、画面に出た URL を自分でブラウザに貼り付け、表示された確認コード（ワンタイムコード）を入力してください。

::: tip gh がまだ入っていないとき
GitHub 用の小さな道具（gh）が未導入でも、次を実行すれば自動で入ります。

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/ensure-gh.js"
```
:::

### 会社プロキシ下で認可が失敗します

社内ネットワークの設定が原因のことが多いので、情シス（情報システム部）に相談してください。

会社のネットワークには、外部サイトへの通信を制限する仕組み（プロキシ／ファイアウォール）があります。claude.ai と github.com にアクセスできる状態か、設定とあわせて確認してもらってください。

### ツール名のプレフィックスが資料と違います

**サービス名（Notion、Slack など）で目的のツールが見えていれば、接続は成功しています。** 頭の文字列が資料と違っても問題ありません。

`mcp__claude_ai_Notion__*` のような、ツール名の頭につく識別子（プレフィックス）は、claude.ai の接続設定（Connectors）の構成によって変わります。

::: info 機密のチェックには影響しません
個人情報（マイナンバーやカード番号など）を外に出さないためのチェック機能は、この頭の文字列に関係なく働きます。プレフィックスが違っても、機密のブロックは効いたままです。
:::

## 使い方

### 思っていたのと違うツールに振り分けられました

「Slack ではなく Notion にして」のように、行き先を言い直してください。それで切り替わります。

アシスタント（秘書）は、あなたの言葉やキーワードから「どのアプリの仕事か」を推測して振り分けます。推測なので、ときどき外すことがあります。

同じ言い直しが何度も続くと、その好みを覚えて以後は自動で正しく振り分ける提案（[自動ルール化](/guide/personalization#_1-自動ルール化-rule-learning)）が出ることがあります。

### 書き込みのたびに確認が出るのは仕様ですか

はい、仕様です。送信・作成・更新・PR 作成のように**何かを書き込む・送る操作は、毎回あなたに確認**します（[permission の ask 分類](/guide/security#l2-permission-allowlist)）。

ただ読むだけの操作は、確認なしでそのまま実行されます。送る前に一呼吸おく安全装置だと考えてください。

### 操作がブロックされました

危ない操作・送ってはいけない情報を、システムが手前で止めた状態です。原因は次の2つのどちらかです。

- **個人情報・機密の検知**: マイナンバー・カード番号・「社外秘」ラベルなどが入ったまま、外部に送ろうとした。該当部分を消してから送り直してください。
- **「禁止」の操作**（操作ルールの deny）: ファイルの強制削除（`rm -rf`）、変更の強制上書き（`git push --force`）、`.env` の読み取りなど、壊す・危険なものは、そもそも実行できないようにしてあります。

詳しくは **[セキュリティと権限](/guide/security)** を参照してください。

### ブラウザ操作が必要と言われました

ブラウザを自動で動かす機能は標準では入っていません。必要なときだけ、次を打って追加してください。

```
/plugin install browse@<repo>
```

Notion・Slack・GitHub・Google Drive の中で済む作業なら、ブラウザなしでそのまま進められます。

## パーソナライズ

### 勝手にルールやエージェントが増えませんか

増えません。**あなたが承認したものだけ**が残ります。

ルールを覚える・その仕事専門のアシスタントを作る・新しい機能（スキル）を入れる、これらはすべて事前にあなたに確認します。断れば実行されませんし、何度も同じ提案でしつこく聞くこともありません（続けて断ると、しばらく提案自体が止まります）。

### 作られた専用エージェントを消したい

専用の執務室の中（`~/my-agent/.claude/agents/<slug>.md`。POSIX: `$HOME`、Windows: `%USERPROFILE%` の下）のファイルを削除すれば、その仕事専門のアシスタントは呼ばれなくなります。

削除は次回の起動時に自動で気づかれ、管理用の `~/.belta/agents/AGENTS.md` に「いつ消したか（deleted_at）」が記録されます。あなたが手で台帳を直す必要はありません。

### Windows でも同じように動きますか

はい、同じように動きます。

裏側の処理は Claude Code に同梱された Node.js で書かれていて、特定の OS だけで動くコマンドに頼っていないためです。専門アシスタントや手作り道具は、専用の執務室（`~/my-agent/.claude/`）にそのまま置くだけなので、OS ごとに挙動が変わるショートカット（symlink）の作成にも頼っていません。

### プロフィール深化（user-model）で覚えた内容を確認・消したい

あなたのPC内の個人フォルダにあるメモ（`~/.belta/user-model.md`。POSIX: `$HOME`、Windows: `%USERPROFILE%` の下）を開けば、秘書があなたについて覚えた「傾向」を確認できます。消したい項目はその行を削除すれば反映されます。

これは「指示」ではなく観察した「傾向」なので、はっきりした指示（プロフィールやルール）より優先されることはありません。初回セットアップで作ったプロフィール本体（`~/.belta/profile.md`）は書き換えられないので、安心してください。

### 同じ事実の間違いを何度も繰り返されます（事実訂正メモリ）

その場で「それは違う」「正しくは〜」と正してください。同じ間違いが 2 回以上くり返されると、秘書が「正しい事実を覚えておきますか？」と確認します。承認すると、以降は毎回その正しい事実を踏まえて答えるようになります（[事実訂正メモリ](/guide/personalization)）。

覚えた事実は `~/.belta/memory/MEMORY.md` で確認・修正できます。なお、書き方や口調の好みの訂正は、こことは別の[自動ルール化](/guide/personalization#_1-自動ルール化-rule-learning)が担当します。

## 定期実行・振り返り

### 振り返り（insights）に誤った情報が入っていました

振り返りは、たまった業務日誌（`~/.belta/notes/`）を材料に要約しています。元のメモに事実と違う記述があれば、その日付のファイルを直してから、もう一度 `/insights` を実行してください。

もし秘書が事実を取り違えていたら、その場で正してください。同じ間違いが続くと[事実訂正メモリ](/guide/personalization)が覚えて、以降は繰り返さなくなります。

### 登録した定期作業が、指定した時間に実行されませんでした

定期作業は **Claude Code（アプリ）を開いている間**に動きます。実行時刻にアプリを閉じていた場合は、次に開いたときにまとめて実行されます。

それでも動かないときは、`/workflow-schedule` で「登録した定期作業の一覧を見せて」と頼み、予定が残っているか・次の実行時刻がいつかを確認してください。お使いの環境によっては自動実行の仕組みが使えないことがあり、その場合は手動で `/insights` などを実行する運用に切り替える案内が出ます。

### 登録した定期作業を止めたい・消したい

`/workflow-schedule` を実行し、「○○の定期作業を止めて（消して）」と伝えてください。対象を選んで停止・削除できます。

## 更新（アップデート）

### 秘書は自動で最新版になりますか

**なりません。** 本来は自動で入れ替わる仕組みがあるのですが、Claude Code 側の既知の不具合でうまく働きません。そのため、放っておくと古い版のまま使い続けることになります。

改善や修正を受け取るには、ときどき次のどちらかをしてください（確認だけなら数秒で終わります）。

- `/workflow-update` と打つ
- 「アップデートして」「更新ある？」と話しかける

新しい版があるときだけ「v○○ → v△△ に更新しますか？」と聞かれます。無ければ「すでに最新です」と返って終わりです。月に 1 回程度でも十分です。

### 更新したのに、動きが変わりません

**入れ替えたあと、Claude Code を閉じて執務室フォルダを開き直す**必要があります。開いたままだと、そのあいだは古い版が動き続けます（更新の作業をしているのが古い版の秘書自身、というわけです）。

開き直すと「v○○ に更新されました」というお知らせが出ます。それが出れば反映済みです。

なお、すでに作られた画面（アバターのダッシュボードなど）は**作り直すまで古いまま**です。`/avatar`・`/usage`・`/report` をもう一度実行すると最新の内容で作り直されます。

### 更新に失敗したと言われました

秘書が手で実行できる 2 つのコマンドを提示します。多くは一時的なネットワークの問題なので、少し待って `/workflow-update` をもう一度試すだけで解決します。

繰り返し失敗する場合は、情シス推進担当に**提示されたコマンドと、返ってきたメッセージ**を添えて連絡してください。

## データ・プライバシー

### 自分のプロフィールやメモはどこに保存されますか

すべてあなたのパソコンの中、`~/.belta/` フォルダ（POSIX: `$HOME`、Windows: `%USERPROFILE%` の下）に保存されます。

このフォルダは共有用の置き場（リポジトリ）から外す設定になっているので、**チームに勝手に共有されることはありません**。

### 認証情報はローカルに平文で保存されますか

されません。パスワード代わりの鍵が、そのまま読める形でパソコンに置かれることはありません。

Notion・Slack・Google Drive の鍵は claude.ai 側の安全な保管庫に、GitHub の鍵はパソコン標準の資格情報の金庫（macOS のキーチェーン／Windows の資格情報マネージャー）に預けられます。

## それでも解決しないとき

情報システム部の推進担当に、**症状**と**再現する手順**を添えて連絡してください。

そのとき、機密情報そのもの（マイナンバー、カード番号、社外秘の中身など）は連絡に書かないでください。状況の説明だけで十分です。
