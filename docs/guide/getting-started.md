# 導入手順（5 分セットアップ）

**このページを終えると、Belta ワークフローエージェントを業務で使い始められます。** 必要な時間は約 5 分。難しい設定はなく、画面の案内にしたがって質問に答え、いくつか「許可」ボタンを押すだけです。

::: tip このエージェントは「4つのアプリを使い分ける優秀な秘書」
Notion・Slack・Google Drive・GitHub の 4 つの道具を、用件に応じて自動で使い分けてくれるアシスタント（秘書）です。あなたは普通に話しかけるだけで、秘書が適切な道具を選んで動いてくれます。このページでは、その秘書を「雇い入れる」初期手続きを行います。
:::

順に進めてください。

## いちばん簡単な始め方：インストーラーをダウンロード

**結論から言うと —** お使いの OS のインストーラーをダウンロードしてダブルクリックすれば、専用の執務室（フォルダ）作りとエージェント本体の取り込み準備が**自動で**終わります。下のボタンからどうぞ。

<p>
  <a class="vp-button" href="https://github.com/belta-group/belta-workflow-agent/releases/latest/download/belta-installer-macos.zip"><strong>⬇️ macOS 用インストーラー</strong></a>
  &nbsp;
  <a class="vp-button" href="https://github.com/belta-group/belta-workflow-agent/releases/latest/download/belta-installer-windows.zip"><strong>⬇️ Windows 用インストーラー</strong></a>
</p>

使い方は 3 ステップだけです。

1. ダウンロードした zip を展開し、**macOS は `install.command`／Windows は `install.bat`** をダブルクリックする。
2. 画面の案内にしたがって**会社のメールアドレス（`@belta.co.jp`）**を入力する。これで `~/<メールの@より前>-agent` という専用の執務室が用意され、エージェントを取り込む準備が整います。
3. 案内された専用フォルダを Claude Code で開き、`/workflow-setup` を実行する（このあと [Step 3](#step-3-初回セットアップを始める) 以降と同じ）。

::: warning このインストーラーが自動化するのは「準備」までです
インストーラーは、フォルダ作成とエージェント取り込みの**下ごしらえ**を肩代わりするものです。次の 2 つは引き続き必要です。
- **Claude Code（claude.ai の Max / Team / Enterprise プラン）の導入** … エージェントが動く土台。未導入なら先に入れてください（次の「前提の確認」参照）。
- **5 問の自己紹介と 4 アプリの「許可」操作** … プロフィール登録（[Step 4](#step-4-5-問オンボーディング)）と OAuth 接続（[Step 5](#step-5-4-ツールの-oauth-接続)）は、安全のため必ずあなた自身の操作で行います。
:::

::: tip macOS で「開発元を検証できません」と出たら
初回だけ、`install.command` を**右クリック →「開く」**を選んでください（ダブルクリックの代わり）。一度許可すれば次回からはダブルクリックで開けます。
:::

::: info コマンドで入れたい方はこのまま下へ
インストーラーを使わず、Claude Code にコマンドを打って導入することもできます。その場合は下の [Step 1](#step-1-専用の執務室-フォルダ-を用意する) 以降の手順に進んでください（どちらの方法でも到達点は同じです）。
:::

## 前提の確認

**まず、お使いの環境がこのエージェントを使える状態か確認します。** 次の 2 点を満たしていれば準備完了です。

- **Claude Code（クロード・コード）が入っていること** … このエージェントが動く土台のアプリです。
- **claude.ai のプランが Max / Team / Enterprise のいずれかであること** … 4 つのアプリと安全につなぐ機能（後述の Connectors）を使うために必要です。

::: info GitHub を使う予定でも、いま準備は要りません
GitHub 用の小さな道具（gh）が入っていなくても大丈夫です。セットアップの途中で自動的に導入されます（[Step 5](#step-5-4-ツールの-oauth-接続) で説明）。手作業でのインストールは不要です。
:::

## Step 1. 専用の執務室（フォルダ）を用意する

**最初に、この秘書だけが働く「専用の執務室」を 1 つ用意します。** ホームの中に `my-agent` という名前のフォルダを作り、**そのフォルダの中で Claude Code を開いて**ください（POSIX: `$HOME/my-agent` / Windows: `%USERPROFILE%\my-agent`）。ターミナルならそのフォルダに移動（`cd`）してから起動、エディタなら「フォルダを開く」でこのフォルダを選びます。

この秘書は、関係ない作業中に顔を出さないよう、**この執務室の中でだけ**働く設計です。先に部屋を用意し、その部屋の中で次の Step のインストールを行うことで、最初から「この部屋限定」で秘書を雇い入れられます。

::: tip なぜ先にフォルダを作るのか
あとで実行する初回セットアップ（`/workflow-setup`）も、同じ `~/my-agent` を専用の執務室として使います。**先に自分でこの部屋を用意し、その中でインストールしておく**と、秘書は最初からこの部屋限定で有効になります（セットアップは、この既にある部屋をそのまま引き継ぎ、別名の部屋を作り直したりはしません）。
:::

## Step 2. プラグインをインストール

**Step 1 で開いた執務室の中で**、エージェント本体を取り込みます。下の 2 行を Claude Code に入力するだけです。

```
/plugin marketplace add belta-group/belta-workflow-agent
/plugin install workflow@belta-workflow-agent
```

1 行目で「社内のアプリ置き場（マーケットプレイス）」を登録し、2 行目でそこから `workflow` プラグイン（エージェント本体）を取り出して導入します。本屋を登録してから、目当ての本を 1 冊持ち帰るイメージです。

2 行目を実行すると、**「どこで使えるようにするか（スコープ）」を選ぶメニュー**が表示されます。次の 3 択のうち、**いちばん下の「このフォルダだけ（local scope）」を選んでください**（カーソルは初期状態で先頭の User に当たっているので、↓ キーで下まで動かして選びます）。

| メニュー表示 | 意味 | 選ぶ？ |
| --- | --- | --- |
| Install for you (user scope) | すべての場所で有効（全ディレクトリで発火） | ✗ |
| Install for all collaborators on this repository (project scope) | この repo を共有する全員で有効 | ✗ |
| **Install for you, in this repo only (local scope)** | **いま開いているこのフォルダだけで有効** | **✓ これを選ぶ** |

Step 1 で `~/my-agent` の中で Claude Code を開いているので、「このフォルダだけ（local scope）」を選べば、秘書は `~/my-agent` の中でだけ働き、関係ない作業中に顔を出すことはありません。

::: warning コマンドの `--scope` フラグは当てにしない（メニューで選ぶ）
バージョンによっては `--scope local` のようなフラグを付けても無視され、結局このメニューが出ます。**フラグ任せにせず、必ずメニューで「このフォルダだけ（local scope）」を選んでください。** もし間違って「すべての場所（User）」で入れても大丈夫 — 次の Step の初回セットアップが、専用の執務室だけで働くよう整えます。
:::

## Step 3. 初回セットアップを始める

**同じ執務室（`~/my-agent`）の中で**、新しい会話（セッション）を開いて、「セットアップして」と話しかけるか、`/workflow-setup` を実行してください。これで 5 問の初期設定が順番に始まります。

```
/workflow-setup
```

確実なのは `/workflow-setup` を打つ方法です。新しく入った秘書に「まず自己紹介の登録をお願い」と最初に声をかけるイメージです。

::: tip 執務室はそのまま引き継がれます
セットアップは、Step 1 で用意した執務室（`~/my-agent`）を**そのまま専用の部屋として引き継ぎます**（あなたが既にこの部屋で秘書を有効にしているため、新しく別の部屋を作り直したりはしません）。以降、秘書はこの部屋の中でだけ働きます。次回からも、**この `~/my-agent` フォルダを開いて**話しかけてください（POSIX: `$HOME/my-agent` / Windows: `%USERPROFILE%\my-agent`）。
:::

::: warning 入れただけ・待つだけでは始まりません
プラグインを入れただけでは、セットアップは自動実行されません。画面に案内が勝手に表示されるのを待っても始まりません。**あなたから「セットアップして」と声をかける**か、**`/workflow-setup` を実行する**ことで始まります。
:::

::: tip プラグインを入れたその会話では始められないことがあります
プラグインを入れた「その瞬間」に開いていた会話では、うまく始められないことがあります。その場合は Claude Code をいったん開き直し、**新しい会話**で `/workflow-setup` を実行してください。
:::

::: details しくみ
新しいセッション開始時に `SessionStart` フック（`hooks/session-start.js`）が動き、未セットアップなら「セットアップを始めるよう」アシスタントへ指示（追加コンテキスト）を渡します。ただしこれは**画面に表示される案内ではなく**、アシスタントへ内部的に渡る指示です。これだけでアシスタントが自分から切り出すこともありますが、確実ではありません。確実に始めるには、上記のとおり自分から `/workflow-setup` を実行してください。完了の目印 `~/.belta/.onboarded` ができるまでは、セッションごとに同じ指示が渡されます（やり残しの拾い直し）。
:::

## Step 4. 5 問オンボーディング

**ここでは、秘書にあなたのことを覚えてもらいます。** 5 つの質問に答えるだけ。一度に全部ではなく、1 問ずつ順番に聞かれるので迷いません。選択式の質問はボタンで選べます。

使うほど手に馴染む道具のように、ここで答えた内容をもとに、秘書はあなた好みの動き方を覚えていきます。

聞かれるのは次の 5 つです。

1. **お名前**
2. **部署**（例: 情報システム部、営業部）
3. **主な業務**（3 つまで。例: Notion スキーマ設計、週次ワークフロー改善、社内問い合わせ対応）
4. **扱う情報の機密度**（**公開 / 社外秘 / 極秘** の 3 択）
5. **つなぎたいアプリ連携機能（MCP）**（Notion / Slack / Google Drive / GitHub から複数選べます）

**メールアドレス**は初期値が表示されます。合っていればそのまま承認、違えば直してください。

::: info 「機密度」はあなたを守るための設定です
ここで選んだ機密度は、情報を社外に送る前にどれだけ厳しく確認するか（[個人情報を見張るしくみ（PII 検知フック）](/guide/security#l1-pii-検知フック)の警告の出かた）に反映されます。**極秘**を選ぶほど、送信前のチェックが慎重になります。神経質な秘書ほど、機密書類を外に出す前に何度も「本当に出していいですか」と確認してくれる、というイメージです。
:::

答えた内容は、あなたのパソコンの中だけに保存されます（個人データなので、共有リポジトリには上がらないよう `.gitignore` で除外済みです）。

::: details 保存先の詳細
- `~/.belta/profile.md` … 人間が読めるプロフィール正本（氏名・部署・機密度・主要業務・接続ツール）
- `~/.belta/config.yaml` … 機械が読む設定（`owner_email` / `confidentiality` / 専用の執務室の場所 `agent_home` / 自動化機能のフラグ）
- `~/.belta/notes/` `inbox/` `todos/` … 日々の記録用ディレクトリ
- `~/my-agent/`（専用の執務室）… ここで秘書が働きます。秘書が自分で覚えた「専門のアシスタント」や「手作りの道具」は、この部屋の中（`~/my-agent/.claude/`）に貯まります。

> あなたのパソコン内の個人フォルダ（`~/.belta/`）と専用の執務室（`~/my-agent/`）の、ホームディレクトリ部分は Mac/Linux では `$HOME`、Windows では `%USERPROFILE%` から自動で解決されます。どちらも個人データなので、共有リポジトリには上がらないよう保護されています（執務室には自動で `.gitignore` が用意されます）。
:::

## Step 5. 4 ツールの OAuth 接続

**ここで、秘書が 4 つのアプリを使えるよう「鍵あけ」をします。** といっても、パスワードを渡すわけではありません。

::: tip 合鍵は渡しません。「許可」ボタンを押すだけ
接続には「許可」ボタンで安全につなぐ方式（OAuth）を使います。これは、家の合鍵を渡してしまうのではなく、訪問のたびにインターホンで「どうぞ」と許可するイメージです。各アプリの画面で「許可」ボタンを押すだけで、長いパスワードのような接続キー（API キー）を手で書き写す必要はありません。
:::

Step 3 で選んだアプリについて、接続の案内が出ます。やることはアプリごとに次のとおりです。

- **Notion / Slack / Google Drive** … claude.ai の画面で「設定 → 接続設定（Connectors）」を開き、各サービスの「許可」を押します。
- **GitHub** … ターミナルで `gh auth login --web` を 1 回実行します。`gh`（GitHub 用の小さな道具）が入っていなくても、まず `node "${CLAUDE_PLUGIN_ROOT}/scripts/ensure-gh.js"` を実行すれば自動で導入されます。

下が、上の内容を表にまとめたものです。

| ツール | 操作 |
| --- | --- |
| Notion / Slack / Google Drive | claude.ai → Settings → Connectors（接続設定）で各サービスを認可（「許可」を押す） |
| GitHub | `gh` 未導入なら `node "${CLAUDE_PLUGIN_ROOT}/scripts/ensure-gh.js"` で自動導入 → ターミナルで `gh auth login --web` を 1 回実行 |

::: info GitHub 用の道具は自動で入ります
`gh`（GitHub 用の小さな道具）が見つからないときは、`node "${CLAUDE_PLUGIN_ROOT}/scripts/ensure-gh.js"` を実行すると、お使いの OS の標準的なアプリ導入ツール（Mac は Homebrew、Windows は winget）を使って自動でインストールしてくれます。自分で公式サイトを探してダウンロードする必要はありません。
:::

詳しい手順と「ちゃんとつながったか」の確認方法は **[4 ツール OAuth 接続](/guide/oauth-setup)** を参照してください。

## Step 6. 権限ルールの適用（必要な場合のみ）

**このステップは、多くの人にとっては不要です。** 何もしなくても自動で設定されることがほとんどなので、まずは読み飛ばして構いません。うまく反映されなかったときの「予備の手段」として用意されています。

ここで言う権限ルールとは、秘書がやってよい操作を 3 段階に仕分けたもの（操作ルール：やってよい / 確認する / 禁止）です。このプラグインは、その操作ルール（allow / ask / deny）を同梱の `.claude/settings.json` で配布します。多くの環境では自動で取り込まれるため操作は要りませんが、自動で取り込めない環境向けに、手動で適用する手段を用意しています。

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/apply-permissions.js" --target "<専用の執務室>/.claude/settings.local.json"
```

- `<専用の執務室>` は Step 1 で用意した `~/my-agent` フォルダの場所です。初回セットアップ（`/workflow-setup`）はこの適用まで自動で行うので、通常この手作業は不要です。
- 既存の設定はそのまま残り、同じ内容が重ねて足されることもありません（何度実行しても結果は同じ＝冪等）。
- 実際に適用する前に「何が変わるか」だけ見たいときは、末尾に `--dry-run` を付けます。
- 詳しくは **[セキュリティと権限](/guide/security#l2-permission-allowlist)** を参照してください。

## 完了

**おつかれさまでした。これでセットアップは完了です。** すべて終わると目印のファイル `~/.belta/.onboarded` が作られ、以降は初回案内が出なくなります。

::: info やり残しがあっても大丈夫
セットアップが終わるまでは、`/workflow-setup` でいつでも続きから再開できます（次のセッションではアシスタントの方から促すこともあります）。先に別の用件を片付けたいときは、後回しにして構いません。
:::

セットアップ後は、**専用の執務室（`~/my-agent` フォルダ）を開いて** `/workflow` で呼び出すか、そのまま普通に話しかけるだけ。内容に応じて秘書が 4 つのアプリへ自動で振り分けてくれます。次は **[基本的な使い方](/guide/usage)** へ進んでください。
