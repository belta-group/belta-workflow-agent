# パーソナライズ機能

**このページは「このエージェントが、使うほどあなた専用に賢くなっていく仕組み」の話です。** 読むと、あなたの口ぐせや段取りを覚えてくれる秘書のように、同じ説明を繰り返さなくて済むようになります。しかも勝手に覚えることはなく、覚える前に必ず「これ覚えていい？」と確認します。

イメージは、**使うほど手に馴染む道具**です。買ったばかりの道具は誰の手にも合いませんが、使い込むほどあなたの手の形になじみます。このエージェントも、あなたの仕事のクセを少しずつ覚えて、あなた専用になっていきます。

::: tip 安心してください：勝手には増えません
ここで紹介する 4 つの仕組みは、すべて **あなたが「はい」と答えたものだけ** を覚えます。あなたの知らないうちにルールや担当者が増えていくことはありません。
:::

覚え方には「細かさ」の違う 4 種類があります。詳しくはこのあと 1 つずつ説明しますが、ざっくり言うと次のとおりです。

- **自動ルール化** … 「次からはこうして」と一度言えば、秘書がメモして以降ずっと守ってくれる
- **自動エージェント化** … 同じ種類の仕事が増えてきたら、その仕事専門の担当者を新しく雇う
- **自動スキル提案** … 道具箱に無い便利な道具を、秘書が「これ要りますか？」と勧めてくれる（**既製品を買ってくる**）
- **自動スキル化** … 同じ専門の仕事が何度も続いたら、その仕事専用の道具を秘書が**手作りする**（**オーダーメイドであつらえる**）

補足として、それぞれが「何を覚えるか」と「どこに保存するか」を表にまとめます。保存先のパス（保管場所の住所のようなもの）は、後で見返したいときの参考です。

| 仕組み | 覚えるもの | 保存先（保管場所） |
| --- | --- | --- |
| **自動ルール化**（rule-learning） | 言葉で言い表せる、あなたの好み・訂正 | `~/.belta/rules/` |
| **自動エージェント化**（agent-learning） | 繰り返し出てくる「仕事の分野そのもの」 | 専用の執務室 `~/my-agent/.claude/agents/` |
| **自動スキル提案**（skill-suggestion） | 今の道具では手間がかかる作業に効く、既にある追加の道具 | `SKILLS.md` で管理、`/plugin install` で導入 |
| **自動スキル化**（skill-authoring） | 何度も続く専門の仕事に合わせた、専用の手作り道具 | 専用の執務室 `~/my-agent/.claude/skills/<name>/` |

## 共通の承認フロー

**4 つの仕組みに共通するのは、「勝手に進めない。必ず『やっていい？』と確認してから覚える」というルールです。** だから安心して使えます。

流れはどれも同じで、3 ステップです。

1. **気づく** … 「これは覚えた方がよさそう」とエージェントが気づきます。
2. **確認する** … 「保存する / 今回は不要」のような選ぶだけの画面（選択 UI）で、あなたに尋ねます。自由に書き込む欄もあるので、迷わず答えられます。
3. **覚える / 見送る** … あなたが「はい」と答えたものだけ保存し、「いいえ」なら何もしません。

::: tip しつこく聞かれません
「いいえ」と答えたことは記録に残るので、同じことを何度も提案されません。さらに、同じ提案を続けて何回か断ると、その提案は **しばらく止まります（同じ提案を止める期間＝冷却）。**
:::

## 1. 自動ルール化（rule-learning）

::: tip これは何？
**「次からはこうして」と一度言えば、秘書がメモして以降ずっと守ってくれる** 仕組みです。同じ訂正を何度もさせなくて済みます。もちろん、メモする前に「覚えていい？」と確認します。
:::

あなたの好みや訂正を **言葉のメモ（覚えさせる決まりごと＝ルール）** として残し、次回以降のやりとりにも引き継ぎます。たとえば「日付の書き方」を一度教えれば、毎回言わなくても守ってくれます。

### 検知トリガ

エージェントは、次のような場面で「これはルールにすべきかも」と気づきます。**ポイントは「これからもずっとそうしてほしい」というサインがあるかどうか** です。

- **「これからずっと」という言い方**: 「次回からは」「今後は」「毎回」「いつも」「常に」「前にも言ったけど」など。
  - 逆に「今回だけこうして」という一度きりの依頼は、ルールにはなりません。「ずっと」を表す言葉が目印です。
- **同じ訂正を 2 回以上**: たとえば「日付は YYYY-MM-DD で」と続けて 2 回直した、など。
- **判断への強い肯定**: 当たり前ではない判断に「それで正解」「完璧」と強く褒めたとき。

### 承認するとどうなるか

**あなたが承認すると、その決まりごとがメモとして保存され、次回以降は自動で守られます。** 同じ指示を毎回繰り返す必要がなくなります。

技術的には、`~/.belta/rules/<slug>.md`（`slug` はファイル名用の短い識別子）にルールが保存され、一覧表の `RULES.md` に追記されます。以降のやりとりでは、このメモが自動的に読み込まれます。

> 例: `date-format-iso`（日付は YYYY-MM-DD で書く）、`slack-summary-first`（Slack 共有は冒頭に要約を付ける）

## 2. 自動エージェント化（agent-learning）

::: tip これは何？
**同じ種類の仕事が増えてきたら、その仕事専門の担当者（アシスタント）を新しく雇うイメージ** の仕組みです。一言メモでは足りない「分野まるごと」を任せられる担当者を用意します。雇う前に必ず「雇っていい？」と確認します。
:::

言葉のメモ（ルール）には収まりきらない **「仕事の分野そのもの」** が繰り返し出てきたら、その分野専門のアシスタント（その仕事専門のアシスタント＝subagent）を用意します。一度用意すれば、以降はいつもの呼び出し（`Agent` ツール）から一発で呼べます。

### 検知トリガ

**同じ分野の仕事が別々の機会に 2 回以上出てきたら、専門の担当者を雇う候補にします。** 気づき方は 2 通りあります。

- **過去のメモから気づく**: 直近 5 営業日分のメモ（`~/.belta/notes/`）を見て、同じ分野（例: 「Notion DB 設計」「営業案件レビュー」）の話が 2 回以上出ていたら候補にします。
- **同じ頼みごとの繰り返しから気づく**: 同じ趣旨の依頼を別の機会にもう一度されたとき（例: 「PR の状況を確認して」を別の日にまた依頼）も候補にします。一言メモ（ルール）で済む「言い方の好み」と違い、**仕事の分野まるごとが繰り返されている** ので、担当者を雇う方が向いている、という見分けです。

### 承認するとどうなるか

**あなたが承認すると、その分野専門のアシスタントが用意され、次からはすぐ呼び出せるようになります。** 順を追うと次のとおりです。

1. 専用の執務室の中（`~/my-agent/.claude/agents/<slug>.md`）に専門アシスタントが直接用意されます（仕事の種類に応じて、使うモデルが自動で選ばれます）。
2. 執務室の中に置くだけで、そのフォルダで Claude Code を開いたとき標準の `Agent` ツールからすぐ呼べるようになります（昔のように別の場所へショートカット（分身）を作る手間はなくなりました）。
3. 一覧表 `~/.belta/agents/AGENTS.md`（ホーム側）に、用意したことと採用したことが記録されます。

::: info 任せても、できることは限定されます（権限の継承）
新しく雇うアシスタントには、親の設定（`.claude/settings.json`）のうち **「操作ルール（やってよい＝allow）」のものだけ** が引き継がれます。「確認する（ask）」「禁止（deny）」の操作は渡されません（必要最小限だけ任せる考え方）。また、個人情報（PII）を見張る仕組みは、この専門アシスタント経由の操作にも同じように働きます。
:::

> ショートカット（分身）を手動で消すと、起動時の点検で気づき、`AGENTS.md` に「削除された日時（`deleted_at`）」が記録されます。

## 3. 自動スキル提案（skill-suggestion）

::: tip これは何？
**いまの道具箱に無い便利な道具を、秘書が「これ要りますか？」と勧めてくれる** 仕組みです。勧めるだけで、勝手に道具を増やすことはありません。
:::

メモ（ルール）でも専門アシスタントでも解決しない、**「そもそも今の道具では手間がかかる」** 繰り返し作業に気づくと、それに合った追加の道具（スキル）を提案します。

### 検知トリガ

エージェントは、次のような場面で「もっと良い道具があるかも」と気づきます。

- **今ある道具では手間がかかっている定型作業の繰り返し**: PDF からの文字抽出 / 読み取り（OCR）、表計算の集計、議事録の要約、スライド・資料づくり、画像や図の作成 など。
- **「もっと楽にできない？」という言い方**: 「〜できる？」「〜のやり方」「もっと楽に」「自動化できない？」など。
- これらを、あなたのプロフィール（`~/.belta/profile.md`）に書かれた **主な仕事** と照らし合わせ、あなたの業務に効きそうな候補を優先します。

### 提案・導入フロー

**大事なのは「未確認の道具を勝手に入れない」ことです。** 流れは次のとおりです。

1. **まず手元の道具で足りるか確認** します（同じ提案の繰り返しを防ぐため）。例: PDF 抽出は `pdf` の道具、表計算は `xlsx` の道具で足りることが多いです。
2. 足りなければ、インストールできる道具を `find-skills` で探し、**どこが作ったか・提供元・必要な権限** を確認します。
3. **信頼できる提供元のリスト（信頼できるものだけを載せた許可リスト＝allowlist）** と照らし合わせます。リストには社内の配布元（`belta-group/*`）と Anthropic 公式が入っています。
   - **リストに載っている** → 必要な権限と提供元を添えて「インストールしますか？」と尋ねます。あなたが承認すれば `/plugin install` で導入します。
   - **リストに載っていない**（未審査・第三者） → **自動では入れません。** 提案だけにとどめ、自分で入れる手順と注意点を案内します。
4. 導入後は、ちゃんと使える状態かを確認し、一覧表 `SKILLS.md` に記録します。

::: warning 未確認の道具は自動で入りません
安全のため、許可リストに載っていない道具が勝手にインストールされることはありません。新しく入れた道具にも、個人情報（PII）を見張る仕組みが同じように働きます。
:::

## 4. 自動スキル化（skill-authoring）

::: tip これは何？
**同じ専門の仕事が何度も続いたとき、その仕事専用の道具を秘書が手作りしてくれる** 仕組みです。買ってくる（自動スキル提案）のではなく、あなたの仕事に合わせて **オーダーメイドであつらえる** イメージです。作る前に必ず「作っていい？」と確認します。
:::

3 番の「自動スキル提案」が **既製品を買ってくる** のに対し、こちらは **あなた専用の道具を新しく手作りする** 点が違います。世の中に合う道具が見つからない、けれど同じ専門作業を毎回手でこなしている——そんなときの仕組みです。

### これは「最後の手段」です

新しい道具を手作りするのは、4 つの中で一番おおごとです。手作りの道具は **使う場面を秘書が自動で見つけて働く** ため、作りが甘いと余計な場面で出てきてしまいます。そこで、**ほかの 3 つで解決できないと分かったときだけ** 手作りに進みます。具体的には、次の 4 つが **すべて当てはまったとき** だけ提案します（1 つでも外れたら、その担当の仕組みに任せます）。

1. **同じ専門の仕事が 3 回以上くり返されている**（担当者を雇う＝自動エージェント化の「2 回」より高いハードル）。
2. **一言メモ（ルール）では書ききれない**（手順が長い・専門知識が要る）。
3. **担当者に丸投げ（エージェント）するより、いつもの作業の流れに自動で差し込みたい**。
4. **既にある道具（自動スキル提案）を探しても見つからない**。

::: info 「これスキルにして」と頼んでもOK
あなたから「いつもの手順を道具にして」と直接頼めば、回数のハードル（3 回）は省けます。ただしその場合も、一言メモ・担当者・既製品で足りないかは確認します。
:::

### 承認するとどうなるか

**あなたが承認すると、その仕事専用の道具が手作りされ、次から同じ場面で自動的に働きます。** 順を追うと次のとおりです。

1. 専用の執務室の中（`~/my-agent/.claude/skills/<name>/`）に専用の道具一式（手順書 `SKILL.md` と、必要なら参考資料や補助プログラム）が直接作られます。
2. 執務室の中に置くだけで、そのフォルダで Claude Code を開いたときすぐ使えるようになります（昔のように別の道具置き場へショートカット（分身）を作る手間はなくなりました）。
3. 一覧表 `~/.belta/skills/AUTHORED.md`（ホーム側）に、作ったことと採用したことが記録されます（既製品の導入記録 `SKILLS.md` とは別の帳簿です）。

::: info 手作りでも、できることは増えません（権限は同じ）
手作りした道具も、使える操作は本体の設定（操作ルール allow／確認 ask／禁止 deny）の範囲内です。道具を作っても権限の壁は広がりません。個人情報（PII）を見張る仕組みも、手作りの道具の中の操作に同じように働きます。
:::

## 蓄積物の置き場所まとめ

**覚えた内容は、すべてあなたのパソコンの中だけに保存されます。** 共有リポジトリに送られることはないので、あなた専用のままです。保存先は 2 か所に分かれます — 機密になりがちな記録は **あなた専用の個人フォルダ（`~/.belta/`）** に、秘書が手に入れた専門アシスタント・手作り道具の実体は **専用の執務室（`~/my-agent/`）** に置かれます。

参考として、何がどこに保存されるかを表にまとめます。「実体」は本物の保存場所、「インデックス」は中身を一覧できるメモ帳のようなものです（インデックスは見返しやすいよう、すべて個人フォルダ側にまとめてあります）。

| 種別 | 実体（本物の置き場所） | インデックス（一覧メモ） |
| --- | --- | --- |
| ルール | `~/.belta/rules/<slug>.md` | `~/.belta/rules/RULES.md` |
| アシスタント | `~/my-agent/.claude/agents/<slug>.md`（執務室の中） | `~/.belta/agents/AGENTS.md` |
| スキル（既製品の導入） | `/plugin install` で導入 | `~/.belta/skills/SKILLS.md` |
| スキル（手作り） | `~/my-agent/.claude/skills/<name>/`（執務室の中） | `~/.belta/skills/AUTHORED.md` |

::: info 保存場所について（POSIX: `$HOME` / Windows: `%USERPROFILE%`）
`~/.belta/`（個人フォルダ）と `~/my-agent/`（専用の執務室）の `~` は、あなたのホームフォルダ（POSIX なら `$HOME`、Windows なら `%USERPROFILE%` から解決される、あなた専用の保管場所）を指します。どちらも個人データで、`.gitignore` の設定により **共有リポジトリにはコミットされません**（執務室には初回セットアップが自動で `.gitignore` を用意します）。
:::
