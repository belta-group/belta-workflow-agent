# パーソナライズ機能

このエージェントの核心は、**使うほどあなた専用にチューニングされる**ことです。過去の「中央基盤に全員を合わせる」失敗を反転し、利用者ひとりひとりに寄り添う構造になっています。

パーソナライズは粒度の異なる 3 つの仕組みで成り立ち、いずれも **あなたの承認を取ってから**蓄積されます。勝手に増えることはありません。

| 仕組み | 扱う粒度 | 蓄積先 |
| --- | --- | --- |
| **自動ルール化**（rule-learning） | テキスト指示として一般化できる好み・訂正 | `~/.belta/rules/` |
| **自動エージェント化**（agent-learning） | 繰り返し現れる「業務領域そのもの」 | `~/.belta/agents/` → `~/.claude/agents/` |
| **自動スキル提案**（skill-suggestion） | 手元の道具では非効率な作業に効く追加スキル | `SKILLS.md` で管理、`/plugin install` で導入 |

## 共通の承認フロー

3 つとも、検知 → **提案（選択 UI で確認）** → 承認なら蓄積 / 拒否なら見送り、という流れです。

- 提案は選択肢（「保存する / 今回は不要」など + 自由記述）で出るので、迷わず答えられます。
- **拒否した場合は履歴が残り、しつこく再提案されません。** 同じ対象を所定回数連続で却下すると、一定期間提案が止まります（冷却）。

## 1. 自動ルール化（rule-learning）

繰り返す好み・訂正を **テキストのルール**として蓄積し、以降のセッションをまたいで反映します。同じ訂正を何度もさせないための仕組みです。

### 検知トリガ

- **恒常的な指示のフレーズ**: 「次回からは」「今後は」「毎回」「いつも」「常に」「前にも言ったけど」など。
  - 一度きりの依頼（「今回はこうして」）はルール化されません。**恒常性**を示す語が鍵です。
- **同じ訂正を 2 回以上**: 例「日付は YYYY-MM-DD で」と 2 回続けて直された。
- **非自明な判断への強い肯定**: エージェントの判断に「それで正解」「完璧」と強く肯定したとき。

### 承認するとどうなるか

`~/.belta/rules/<slug>.md` にルールが保存され、インデックス `RULES.md` に追記されます。以降のセッションではこのルールが文脈に載り、同じ指示を繰り返す必要がなくなります。

> 例: `date-format-iso`（日付は YYYY-MM-DD）、`slack-summary-first`（Slack 共有は冒頭に要約を付ける）

## 2. 自動エージェント化（agent-learning）

テキスト指示に収まらない「**業務領域そのもの**」が繰り返し現れたら、その領域専用の Claude Code subagent を生成し、以降は標準の `Agent` ツールから一発で呼べるようにします。

### 検知トリガ

**直近 5 営業日**の `~/.belta/notes/` を走査し、同一の業務領域（例: 「Notion DB 設計」「営業案件レビュー」）への発話が **2 回以上**出現したら候補になります。

### 承認するとどうなるか

1. `~/.belta/agents/<slug>.md` に専用エージェントが生成されます（業務カテゴリに応じて `model` が haiku / sonnet / inherit から選ばれます）。
2. `~/.claude/agents/<slug>.md` に symlink され、標準 `Agent` ツールから呼べるようになります。
   - Windows などで symlink ができない環境では**コピー**にフォールバックします。この場合、正本を更新しても自動反映されない旨が `AGENTS.md` の備考に記録されます。
3. インデックス `AGENTS.md` に生成・採用が記録されます。

::: info セキュリティ境界（権限の継承）
生成される専用エージェントには、親 `.claude/settings.json` の **`allow` の部分集合のみ**が渡されます。`ask` / `deny` のツールは渡されません（最小権限）。また PII 検知フックは subagent 経由の操作にも適用されます。
:::

> symlink を手動で削除すると、起動時の健全性チェックで検知され、`AGENTS.md` に `deleted_at` が記録されます。

## 3. 自動スキル提案（skill-suggestion）

ルールでもエージェントでも埋まらない、**「そもそも今の手元の道具では非効率」**な繰り返し作業を検知し、適合する追加スキルを提案します。

### 検知トリガ

- **手元のスキルで非効率にこなしている定型作業の繰り返し**: PDF 抽出 / OCR、スプレッドシート集計、議事録要約、スライド・ドキュメント作成、画像・図表生成 など。
- **能力探索のフレーズ**: 「〜できる？」「〜のやり方」「もっと楽に」「自動化できない？」など。
- これらを `~/.belta/profile.md` の**主要業務**と照合し、あなたの業務に効く候補に重み付けします。

### 提案・導入フロー

1. **まず手元のスキルで足りないか確認**します（重複提案の抑止）。例: PDF 抽出は `pdf` スキル、スプレッドシートは `xlsx` スキルで足りることが多い。
2. 足りなければ `find-skills` でインストール可能なスキルを検索し、**出典・提供元・要求権限**を把握します。
3. **信頼ソース allowlist**（社内 marketplace `belta-group/*` + Anthropic 公式）に照合します。
   - **allowlist 内** → 要求権限・提供元を併記した上で「インストールしますか？」と提案。承認すれば `/plugin install` で導入します。
   - **allowlist 外**（未審査・第三者） → **自動インストールしません**。提案のみに留め、手動導入の手順と注意点を案内します。
4. 導入後は有効化・読み込みを確認し、`SKILLS.md` に記録します。

::: warning 未審査スキルは自動導入されません
セキュリティのため、allowlist 外のスキルが自動インストールされることはありません。新規に導入したスキルにも PII 検知フックが適用されます。
:::

## 蓄積物の置き場所まとめ

| 種別 | 正本 | インデックス |
| --- | --- | --- |
| ルール | `~/.belta/rules/<slug>.md` | `~/.belta/rules/RULES.md` |
| エージェント | `~/.belta/agents/<slug>.md`（→ `~/.claude/agents/` に symlink） | `~/.belta/agents/AGENTS.md` |
| スキル | `/plugin install` で導入 | `~/.belta/skills/SKILLS.md` |

いずれも `~/.belta/` 配下は個人データで、`.gitignore` により**リポジトリにはコミットされません**。
