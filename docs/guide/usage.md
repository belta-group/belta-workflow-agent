# 基本的な使い方

セットアップが終わったら、あとは **普通に話しかけるだけ**です。エージェントが内容を判断し、最適なツールに振り分けます。利用者はツールの違いを意識する必要がありません。

## 起動

明示的に起動するときは次のコマンドを使います。

```
/workflow
```

セットアップ済みの場合、エージェントはまず `~/.belta/profile.md` を読み込み、あなたの部署・機密度・主要業務を文脈に入れた上で運営モードに入ります。

## 発話 → 4 ツール分岐

発話の内容・キーワード・文脈から、担当ツールが自動で選ばれます。

| 担当ツール | こんな発話のとき | 例 |
| --- | --- | --- |
| **Notion** | メモ整理、議事録、タスク / TODO、ナレッジ、DB 設計 | 「来週の MTG メモを整理して」 |
| **Slack** | 共有、連絡、通知、リマインド、スレッドを読む | 「インフラチームに共有して」 |
| **GitHub** | PR、Issue、コミット、リリース、CI / Actions の状況 | 「先週の PR をまとめて」 |
| **Google Drive** | ファイル検索、PDF / 議事録 / 資料の取り込み | 「議事録 PDF を取り込んで」 |

### 発話例

```
> 来週の定例 MTG のメモを整理して Notion にまとめておいて
→ Notion にページを作成（書き込み前に内容を要約して確認）

> さっきの障害対応の経緯をインフラチームの Slack に共有して
→ Slack に投稿（送信前に内容・チャンネルを確認）

> 先週マージされた PR を一覧で見せて
→ gh CLI で PR を取得（読み取りなのでそのまま実行）

> 共有ドライブにある来期予算の資料を探して要点を教えて
→ Google Drive を検索して読み取り
```

## 複数ツールにまたがる依頼

1 つの依頼が複数ツールに及ぶ場合は、順序立てて 1 つずつ実行し、各ステップの結果を報告します。

```
> 今日の議事録を Notion にまとめて、要点をチームの Slack にも共有して
→ ① Notion にページ作成 → ② その要点を Slack に投稿（各ステップで確認）
```

## 読み取りと書き込みの扱いの違い

| 種別 | 例 | 挙動 |
| --- | --- | --- |
| **読み取り系** | 検索、一覧、閲覧 | 確認なしでそのまま実行 |
| **書き込み系** | 送信、作成、更新、PR 作成 | **実行前に内容を要約して確認**を取る |

特に**社外秘・極秘**の内容を Slack 公開チャンネルや外部へ送る前は、必ず確認が入ります。詳しくは **[セキュリティと権限](/guide/security)** を参照してください。

## 自動で記録されること

意思決定・学び・TODO は、言わなくても `~/.belta/` 配下に日付ごとに記録されます。

- 意思決定・学び・記録 → `~/.belta/notes/YYYY-MM-DD.md`
- クイックメモ・受信箱 → `~/.belta/inbox/YYYY-MM-DD.md`
- TODO → `~/.belta/todos/YYYY-MM-DD.md`

同じ日付のファイルがあれば追記され、既存ファイルは上書きされません。これらの記録は、後述の[パーソナライズ機能](/guide/personalization)が「繰り返し」を検知する材料にもなります。

## ブラウザ操作が必要なとき

Web 上の情報収集や画面操作など **ブラウザ自動化**が必要な依頼は、ブラウザ操作スキルが本体に含まれていないため、未インストールだとその旨が案内されます。全利用者に必要な機能ではないため本体から分離しています。

```
/plugin install browse@<repo>
```

インストール後、改めて同じ依頼をしてください。Notion / Slack / GitHub / Google Drive で完結する範囲であれば、ブラウザなしで進められます。
